Audio Hijack 4.5.9

Released on May 19, 2026

  • Quo VoIP Capture Support
    The Quo desktop app (formerly OpenPhone) is now supported as a VoIP audio source, making it easy to record both halves of a conversation.

  • Settings in the “Broadcast” and “Live Stream” blocks once again save as expected, correcting a regression introduced in Audio Hijack 4.5.8.

  • Minor drawing issues with the “Streaming” animation indicator have been corrected.

  • MacOS 14.4 or Higher Is Now Required
    Audio Hijack now requires MacOS 14.4 or higher. If you're on an older version of MacOS, be sure to see our Legacy Software page.

Audio Hijack 4.5.8

Released on April 27, 2026

  • Audio is once again correctly produced in both channels when using the “Mono” setting in the “Channels” block or the “Mono Signal Processing” setting in the “Speech Denoise” block. This fixes regressions introduced in Audio Hijack 4.5.7.

  • The “Presets” menu in block popovers once again correctly reflects a selected preset, fixing a regression introduced in Audio Hijack 4.5.7.

  • Audio Unit effects from Melda once again properly respond to clicks.

  • Audio Hijack 4.5.8 Is for MacOS 14.4 and Higher
    This variant of Audio Hijack supports MacOS 14.4 and higher. On MacOS 11 through 14.3.1, a different variant is automatically used, with no action required on your part.

Audio Hijack 4.5.7

Released on April 7, 2026

  • Decluttered Menus on MacOS 26 (Tahoe)
    Menus have been decluttered on MacOS 26 (Tahoe), removing icons Apple forced into Audio Hijack. For more details, see our blog post.

  • Unobtrusive Update Notifications
    Audio Hijack’s software update notifications have been modified to be less obtrusive, in the hopes of avoiding disruptions. When the timed automated check detects a newer version, it will no longer pop a dialog in front of your work. Instead, a small “Update Available” indicator will appear in the title bar of Audio Hijack’s “Session List” window, as well as any open sessions. This change makes it easier for you to control when you update to newer versions.

  • When a slider knob is highlighted, holding Option in conjunction with arrow key presses will now move the knob by 0.1x, for making fine adjustments.

  • Launching an application source with the “Open URL” option has been optimised. In particular, starting a radio stream when Apple Music is launched should now be improved.

  • Certain third-party Audio Unit effects, including those from iLok, could previously fail to load. This issue has been corrected.

  • Light mode icons for the on-face menu on the “Channels” block have been improved.

  • The control-click/right-click contextual menu now properly appears for the Code field of the License window, allowing pasting via the mouse. Command-V also continues to work, of course.

  • Several rare crashes have been fixed, including:

    • A crash which could occur when using live streaming to an RTMP server struggled, due to data sent to the network falling behind.

    • A crash of the Audio Unit hosting service, when the Mac woke from sleep.

    • A crash which could occur when .m4a files were recorded with silence monitor engaged.

    • A never-spotted-in-the-wild crash which could occur due to improper resource clean-up when installing Loopback or SoundSource multiple times has been fixed.

  • Audio Hijack’s “License” window now contains a helpful link to access our customer dashboard.

  • Audio Hijack 4.5.7 Is for MacOS 14.4 and Higher
    This variant of Audio Hijack supports MacOS 14.4 and higher. On MacOS 11 through 14.3.1, a different variant is automatically used, with no action required on your part.

Audio Hijack 4.5.3Initial MacOS 26 Support

Released on September 3, 2025

  • Initial Support for MacOS 26 (Tahoe)
    Audio Hijack now has initial support for MacOS 26 (Tahoe), and will no longer warn at launch. However, there are currently two known issues with Tahoe which can result in lost audio.

    • Known issue with sample rate mismatches: If an application is playing audio to an external device whose sample rate does not match that of the system’s default output device, attempting to capture it will fail.

    • Known issue with lost audio from FaceTime and Phone: Attempting to capture audio from FaceTime or the new Phone app fails in certain setups.

    With each of these bugs, silence will be heard, rather than the expected audio. Find more details, including workarounds, in our support article.

    These bugs need to be corrected by Apple, in a future MacOS update. As such, you may wish to consider delaying your upgrade to Tahoe until a later date.

  • New “Notification Center” Special Source
    On MacOS 15 (Sequoia) and higher, the new “Notification Center” special source captures other audio which plays through the system’s Notification Center, such as alarm sounds produced by MacOS’s “Clock” app.

  • An issue where long session lists could jump unexpectedly while scrolling has been resolved.

  • When navigating Audio Hijack’s audio grid via VoiceOver, it once again says “dimmed” for blocks that are turned off. This fixes a regression introduced in 4.5.1.

  • Audio Hijack’s app icon has been modified slightly, to enable it to escape from the icon jail Apple implemented in MacOS 26 (Tahoe).

  • Audio Hijack 4.5.3 Is for MacOS 14.4 and Higher
    This variant of Audio Hijack supports MacOS 14.4 and higher. On MacOS 11 through 14.3.1, a different variant is automatically used, with no action required on your part.

Audio Hijack 4.5.1

Released on May 21, 2025

  • New “Spoken Content” Special Source
    On MacOS 15 (Sequoia), the new “Spoken Content” special source replaces the previous “Text to Speech” special source. It captures audio from the “Accessibility” settings “Spoken Content” area, as well as from apps which play text-to-speech audio via the system (triggered by the “Start Speaking” command in the “Speech” menu).

  • Newly created presets once again enter edit mode when created, allowing their title to be edited immediately. This fixes a regression introduced in 4.4.5.

  • Saved presets in the “10-Band EQ” effect once again correctly show their name, rather than “Manual”, fixing a regression introduced in 4.5.0.

  • The “Transcribe” block no longer shows an error when the selected destination folder has been deleted. Instead, the folder is automatically re-created at the start of the session, matching the behavior of the “Recorder” block.

  • If an output device’s preferred stereo channels update while in use, Audio Hijack will now automatically start using the new channels, rather than requiring a session to be stopped and restarted.

  • Issues where windows moved to secondary displays could have incorrect window widths have been corrected.

  • A drawing issue which could result in dark text on a dark background in the “Recorder” block has been corrected.

  • Imaginando's GRFX Audio Unit plugin will no longer cause the RemoteAUHost process to incorrectly appear in the Dock.

  • Several small improvements have been made to work better with VoiceOver’s “Speak item under the pointer” function.

  • Information regarding Whisper models is now cached by the “Transcribe” block, to prevent redundant network requests.

  • Audio Hijack 4.5.1 Is for MacOS 14.4 and Higher

  • Corrections for Default Settings for VoIP apps in the New “Audio Device Selection” Section of the “Application” Block
    This update fixes a critical issue where attempting to capture from a VoIP app like Zoom or Skype could result in no audio being recorded.
