# 三档版本提取器方案（Deterministic, 不依赖 LLM）

> 目标：把版本号提取从"解析 HTML 猜"升级为"确定性多档递进"，
> 主流软件全覆盖、长尾兜底。全部规则化实现，AI 仅对残余长尾兜底。

## 现状与失败模式

58 例基准（修正期望值后）准确率 45%。剩余失败分三类：

| 失败模式 | 例子 | 根因 |
|---------|------|------|
| **SPA 误报** | notion v0.3、wps v4.2、slack v2.0、mpv v1.2 | 版本藏在 JS/接口响应里，页面可见文字全是随机数字 |
| **深 JS 漏检** | openjdk、opera、inkscape、autohotkey、7zip | 版本要 XHR/JS 跑完才出现，渲染后仍拿不到 |
| **版本体系差异** | golang 23.12（应 1.x）、redis 3.884（应 7.x） | 非递增/1.x 体系，交叉校验可能误判 |

## 三档递进架构

```
L1 浅层（已有）—— HTML 启发式 + 可见正文门控
    适用：传统服务端渲染下载页（nodejs/python/blender/nginx…）
    手段：候选版本 + 下载链接交叉验证 + 出现频次 + 置信度

L2 深度（新增，Playwright/CDP 确定性实现）—— 解决 SPA误报 + 深JS漏检
    1. 网络拦截：捕获页面所有 XHR/fetch 响应，找含 version 字段的 JSON
       → notion/wps/slack 的版本在接口响应里（确定性提取）
       → openjdk/opera 的版本由接口返回（拦截到即拿到）
    2. 运行时全局态：page.evaluate 读 __NEXT_DATA__ / __INITIAL_STATE__ / window 版本全局
    3. 主下载按钮定位：找最大/最突出 download 链接，取 href/text 里的版本
    4. 更新清单探测：尝试 <domain>/latest.json（Electron/Web 应用常见）

L3 版本体系守卫 —— 解决版本体系差异（golang/redis）
    1. 结构化源优先：官方 JSON 端点（如 go.dev/dl/?mode=json 直接给版本数组）
    2. 已知 1.x/特殊体系项目约束候选范围，拒绝突兀跳变
    3. 交叉校验 + 置信度门控（已有）
```

## 为什么 L2 仍是确定性、不是逆向/AI

- **网络拦截** = 读取浏览器自己收到的**公开响应**，找"version"命名字段。站点把这些数据发给每个普通访客，浏览器渲染页面必须先拿到它。
- **运行时全局态** = 读框架（Next.js/React）主动暴露给所有访问者的 `__NEXT_DATA__` 等。
- 全程**不绕过鉴权、不解密、不注入**。本质是"把自己浏览器看到的公开数据结构化读出来"，等同于更新检查器 / 包管理器 manifest 爬取的标准做法。
- 与 AI 的区别：L2 是"找命名字段"的**确定性规则**，不是语义猜测。

## 实施顺序（收益最大优先）

| 阶段 | 内容 | 解决的失败 |
|------|------|-----------|
| **P1** | L2 网络拦截（XHR 响应 version 字段） | SPA 误报 + 深 JS 漏检（两类一起） |
| **P2** | L2 全局态 + 主 CTA 定位 | 补充 P1 覆盖不到的 |
| **P3** | L3 版本体系守卫 + 官方 JSON 端点 | golang/redis/python 类 |

## 准确率预估（诚实）

| 配置 | 预估准确率 | 依据 |
|------|-----------|------|
| 现状（L1 + 注册表，58 例） | 45% | 实测 |
| + 注册表全量补 key（主流软件） | ~70% | 主流软件 winget/brew 基本都有 key，命中即确定性正确 |
| + L2 网络拦截 + 全局态 | ~80% | 解决大部分 SPA 误报 + 深 JS 漏检 |
| + L3 版本体系守卫 | ~85% | 收敛 golang/python/nginx 类 |
| + 结构化源优先（官方 JSON） | ~88% | 更多软件有官方版本端点 |
| 残余长尾（无注册表 + 无结构化源 + 混淆页） | ~12% 需 AI/人工 | 小众/混淆软件 |

**结论：确定性路线可把主流软件覆盖到 ~85-88% 准确率**（比 45% 翻倍且全免费），
残余小众长尾用 LogUp 的 AI/DevTools 兜底。准确率最终由语料真值决定，基准工具持续校准。
