# 700 条标注数据训练评估报告（2026-08-04）

## 结论摘要

用 700 条人工标注数据训练的新分类器（`classifier-700.joblib`），在**同分布测试集**和**跨页 holdout**上都优于旧的 clean 分类器，但仍低于纯启发式在页面级最终版本选择上的表现。当前结论与之前一致：BERT 适合做候选过滤器/排序器，不适合单独替代纯启发式。

## 数据清洗

输入：`feat/annotated-dataset-700` 分支的 `data/dataset-annotated-700.json`（743 页面 / 902 标注）。

清洗步骤（`scripts/clean_700.py`）：

| 步骤 | 结果 |
|---|---|
| 原始标注 | 902 |
| 去重（同 pageId+version+label） | 858（移除 44 重复） |
| ambiguous 转 non_product（明确 build/SDK 语义） | +3 |
| 最终标签 | 正 220 / 负 60 / historical 115 / ambiguous 463 |
| 旧明确噪声负样本补充（仅训练集、每 URL 限量 6） | +约 75 |

标签分布问题：**ambiguous 占比 55%（497/902）**，能直接用于监督训练的仅约 405 条，其中负样本仅 60 条。已通过合并旧 noise 负样本缓解，但新标注自身的 non_product 数量仍然偏少。

按 URL 分组切分（防泄漏）：训练 161 URL / 验证 37 / 测试 49。

## 同分布测试集对比（49 URL / 55 候选）

| 模型 | Acc | F1 | Precision | Recall |
|---|---:|---:|---:|---:|
| 旧 clean | 0.818 | 0.894 | 0.808 | 1.000 |
| **新 700** | **0.873** | **0.921** | **0.872** | 0.976 |

- 负样本误判：旧 10 → 新 6（prec 0.808 → 0.872）
- 正样本召回：1.000 → 0.976（漏 1 条 Autoruns v14.3）
- 剩余误判均为难例：Git 依赖、Ghost 依赖、Electron、Kaleidoscope build 号、Excel Build 号

## 跨页泛化（74 个未参与训练页面）

| 方法 | 命中 expectedVersion | 命中率 |
|---|---:|---:|
| 纯启发式 | 35/74 | 47.3% |
| 旧 clean | 25/74 | 33.8% |
| **新 700** | **30/74** | **40.5%** |

新 700 相对旧 clean 净提升 +5 页：

- 提升 9 页（旧选错、新选对）：libreoffice、gimp、handbrake、shotcut、prometheus、windsurf、rectangle、bitwarden、sketch —— 主要是纠正了把构建号/依赖号当版本（如 v20348.0→v3.2.4、v0.33.1→v3.13.2）
- 退化 4 页（旧对、新错）：firefox、python、everything、redis —— 新模型选到了更低版本（v153.0.1→v8.1、v3.14.5→v3.11.1、v1.4.1→v1.5、v8.8→v7.4）

## 分析

1. **数据量确实提升了判别能力**：同分布负样本误判减少，跨页把明显构建号/依赖号识别出来。说明 700 条标注在"候选是/不是产品版本"的二分类上是有效的。

2. **仍然不足的地方**：
   - 新标注负样本只有 60 条，模型对依赖包（Git/Ghost/Electron）和 build 号的拒识仍不稳；
   - 退化案例显示模型被"语义像版本"的旧版本误导（python v3.11.1 这种完整语义版本）；
   - BERT 没有版本列表/最大版本保护，所以在多版本页面仍会选错当前版本。

3. **架构结论不变**：纯启发式负责候选生成 + 硬规则，BERT 做候选过滤/排序。两者结合的混合排序器（BERT 概率 + 启发式分数 + 版本列表保护）是下一步方向。

## 改进探索（v2 / B / 融合）

在 v1 基础上验证了三条改进路线（74 页 holdout）：

| 方案 | 说明 | 同分布 test F1 | holdout |
|---|---:|---:|---:|
| v1 | evidenceQuote 短文本 | 0.921 | 30/74 |
| v2 | 统一上下文 + 自动 noise 负样本 | 0.941 | 25/74 |
| B | 统一上下文，无 auto-noise | 0.903 | 30/74 |
| **融合** | v1 分类器 + 页内排序 ranker（α=0.7） | — | **32/74** |

**三条结论：**

1. **统一训练/推理上下文没有带来跨页提升**（B = v1 = 30/74）。训练侧 evidenceQuote 与推理侧 HTML 上下文的分布偏移，不是 holdout 瓶颈。

2. **自动 noise 负样本反而有害**（v2 降到 25/74）。原因：auto-noise 教模型压低所有候选的"像版本"概率，导致页内 argmax 选出旧版本（如 prometheus v3.13.2→v0.4.0、bitwarden v2026.3.2→v2022.10.1）。**不加比加好。**

3. **页内排序融合是真正有效的改进**（30→32/74）。用 `historical_product` 构造 `current > historical > non_product` 排序对，训练一个"当前>历史>噪声"的 ranker，与二分类 argmax 融合后，模型能区分"是产品版本"和"是当前版本"两个任务。

纯启发式仍领先（35/74）。BERT 的最佳用法是**候选过滤器（二分类）+ 页内排序（current>historical）+ 纯启发式硬规则保护**。
